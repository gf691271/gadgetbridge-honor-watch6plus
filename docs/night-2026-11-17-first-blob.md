## 关键时序（修正了「ON 藏文件」的模型）

```
08:06:43  FILEDL_INIT sleep_data size=0        <- 08:00 定时同步（R1）
08:06:47  FILEDL_INIT sleep_state size=112     <- 7 条睡眠段，历史最高
08:11      blob 里最后一条 PPG 记录             <- 睡眠会话在此结束
08:58:46  FILEDL_INIT sleep_data size=112632   <- 重连后（R2）
08:58:48  FULLDUMP sleep_data bytes=112632
08:58:48  FULLDUMP saved .../sleep_data_1794877128951.bin
08:58:50  GB 才发出 TRUSLEEP=OFF                <- 在读到之后才发的
```

**修正：** 文件不是「拨 OFF 才可见」——08:58:46 读到 112632 时 TruSleep 还是 ON，
OFF 是 4 秒后才发的。真正的原因是**睡眠会话在 08:11 结束，文件在那之后才可读**，
08:06 那次（会话还没结束）自然是 0。

所以 11-13 那次「10:45 拨 OFF、10:47 出现文件」是**巧合**：会话在 08:50 结束，
我恰好在 10:47 才去读。

### 修正后的模型

| 条件 | 结果 |
|---|---|
| TruSleep = **ON** | 手表在睡眠期间录制原始 PPG |
| 睡眠会话**未结束** | `sleep_data` 返回 0 |
| 睡眠会话**已结束** | 可读，一次读取后清空（0x06 回执） |
| TruSleep = OFF | 不录制（11-13→14、11-14→15、11-15→16、11-09→10、11-10→11 均无新 blob） |

**不需要切换开关。** 只要 TruSleep 常开，早上在会话结束后读一次即可。
